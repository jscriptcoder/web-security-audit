Reviewed 2026-10-13 to 2026-10-14 at skill revision `9884636a8d31072c16f6b900df5897b365ece235`.

**Recommendation:** improve coverage accounting and eval reproducibility before adding more vulnerability guidance. ## Verified issues and proposed fixes

The priorities below are implementation order, not vulnerability severity ratings. F1-F3 affect the inventory's reliability; F4-F6 affect the evidence used to judge the skill.

### F1. Detected Next.js server code is absent from the handler groups

**Evidence:** [the inventory's `handler_groups()`](../../skills/web-security-audit/scripts/sink_inventory.py) accepts only the exact category `Entry points` (lines 90-98 at the reviewed revision). [The frontend searches](../../skills/web-security-audit/references/frontend-frameworks.md) classify Next.js handlers and Server Actions as `Server code in the frontend repo` (line 102). The existing [next-store fixture](../fixtures/next-store/) produces nine leads in that category and zero handler groups. Nine leads do not necessarily mean nine handlers: some matches are imports or related declarations.

**Effect:** a coverage table can omit server surfaces that the scanner has already found. A report following that table can appear complete while skipping them.

**Proposed fix:** represent entry-point status explicitly, or consistently classify the relevant patterns. Treat the resulting groups as discovered candidates and reconcile them with framework conventions and route registration; regex matches alone cannot establish completeness.

**Acceptance:** a regression using `next-store` includes its route-handler and Server Action surfaces in the group table. Existing Node and Java grouping still works. Related imports do not inflate a claim about the number of actual handlers.

### F2. Inventory traversal can leave the requested root

**Evidence:** `_walk()` in [sink_inventory.py](../../skills/web-security-audit/scripts/sink_inventory.py) follows directory links without a resolved-root boundary or visited-directory check (lines 137-159). A Windows junction inside a synthetic target pointed to a sibling directory. The inventory read that sibling's `synthetic.js` and reported it as `linked/synthetic.js`, without a warning or skip. All files were synthetic and inside the review workspace; no real private files or cycles were accessed.

**Effect:** scanning one directory can read files outside the selected scope and misrepresent their location. Cyclic traversal is also a risk suggested by the implementation, but was not exercised in this review.

**Proposed fix:** enforce resolved containment for directory and file links and handle revisited directories. Define any intentional support for external links explicitly. Consider stack detection and skill-copy detection as well as source scanning when enforcing the boundary.

**Acceptance:** tests with a harmless external sentinel prove it is not read by default; links within the root follow the documented policy; a cycle terminates; omitted links have an explicit reason. Test Windows junctions on Windows and symlinks where supported.

### F3. Omitted content is invisible in successful inventory output

**Evidence:** `_text_lines()` silently returns no content for files over 2,000,000 bytes and unreadable files; `_walk()` suppresses directory-read errors. A synthetic oversized JavaScript file containing a route declaration produced no leads, `errors: []` and `skipped: []`. The existing `skipped` field accounts for excluded directories, not all omitted content. The size case was reproduced; the read-error behavior was established by inspecting the implementation.

**Effect:** an auditor cannot distinguish an empty result from an incomplete scan using the output alone.

**Proposed fix:** record omitted paths and reasons and expose partial-scan status. Distinguish deliberate exclusions, binary files, size limits and I/O failures. Carry relevant omissions into the coverage ledger. Choose and document the CLI exit behavior rather than treating every deliberate exclusion as a fatal error.

**Acceptance:** oversized source, unreadable files and unreadable directories are visible with distinct reasons; an ordinary complete scan remains successful; JSON and human-readable output communicate the same limits. Tests assert that a missing route cannot silently become a claim of complete coverage.

### F4. The Juice Shop scrub retains tests containing answers

**Evidence:** [scrub_juice_shop.py](../juice-shop/scrub_juice_shop.py) deletes the top-level `test` directory but leaves frontend specs. The supplied scrubbed copy contained **123 frontend `*.spec.ts` files**. `frontend/src/app/search-result/search-result.component.spec.ts:204-205` names a DOM XSS payload test and supplies its payload; lines 166-169 expect sanitization bypass on script content.

**Effect:** this is additional answer leakage beyond the challenge-helper calls already acknowledged in the eval procedure. Both configurations received the same copy, so this does not establish directional bias. It does make absolute detection scores less persuasive.

**Proposed fix:** remove relevant frontend specs from future scrubbed copies, or explicitly retain and document them as part of the evaluation design. Add a residue check and record what was removed without changing application behavior. Keep answer material outside the auditors' scope.

**Acceptance:** a fixture verifies nested frontend-spec handling, application files survive unchanged except for the documented scrub transformations, and the scrub manifest makes the retention policy reproducible. Update the procedure's claim that tests are removed to match the actual behavior. Retain the known challenge-helper leakage caveat.

### F5. WebGoat rubric A8 overclaims Actuator secret disclosure

**Evidence:** [rubric A8](../webgoat/rubric.md) names OAuth client secrets and keystore passwords as exposed because `env` and `configprops` are published and `/actuator/**` is permitted. The supplied target uses Spring Boot 4.1.1. Review searches found no `show-values` override or custom `SanitizingFunction`. Spring Boot sanitizes endpoint values by default, so those exposure settings alone do not establish disclosure of secret values. See [Spring Boot's endpoint sanitization documentation](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html#actuator.endpoints.sanitization).

**Proposed fix:** credit established unauthenticated metadata and detailed-health exposure with bounded impact. Require additional configuration or response evidence for unsanitized secrets. Add a calibration case for default sanitization.

**Acceptance:** default-sanitized endpoints are not graded as secret-value disclosure; a separate explicitly unsanitized case can receive that credit. Record a rubric revision and annotate historical results instead of silently reinterpreting their scores. No runtime response was captured in this review.

### F6. The WebGoat comment stripper can merge Java tokens

**Evidence:** [strip_java()](../webgoat/scrub_webgoat.py) removes its comment sentinel as an empty string (line 143). The valid input `class Demo { int/**/count = 1; }` becomes `class Demo { intcount = 1; }`. This was reproduced synthetically; damage to an actual supplied WebGoat file was not established.

**Proposed fix:** preserve the lexical whitespace required between tokens while maintaining the scrubber's documented formatting behavior. Add inline-comment cases to [test_scrub_webgoat.py](../../tests/test_scrub_webgoat.py).

**Acceptance:** stripping comments preserves token boundaries, strings, character literals, text blocks and CRLF behavior. Escaped triple quotes are an additional test gap: `_skip_text_block()` uses a simple search for the next delimiter, but that edge case was not reproduced here and is not a separate confirmed finding.

### Selected WebGoat follow-through evidence

These cases were selected from known misses after reading the rubric. They demonstrate why the next step should improve follow-through and evidence for dismissal. Paths below are relative to the target's `src/main/java/org/owasp/webgoat/` unless prefixed with `resources/`; line references describe the supplied scrubbed copy.

| Case | Source trace and bounded conclusion |
| --- | --- |
| Upload containment | `webwolf/FileServer.java:74-93` resolves the client filename beneath a user directory, then deletes/copies without containment enforcement. `webwolf/WebSecurityConfig.java:32-45` permits authenticated uploads. Parent segments can select a sibling user's existing directory, subject to filesystem permissions and parent existence. Unsafe source path confirmed; runtime write/delete and server execution were not demonstrated. |
| Public mail into raw rendering | `container/WebSecurityConfig.java:49-50` permits unauthenticated POST `/mail`. `container/mailbox/MailboxController.java:58-64` saves supplied recipient/content; its reader selects the recipient at line 38. `resources/webgoat/templates/mailbox.html:142` uses `th:utext`. Arbitrary insertion and raw rendering are source-supported; script execution still depends on effective browser policy and was not tested. A private mailbox reader does not make its externally supplied content trustworthy. |
| Cross-user bulk deletion | `container/mailbox/MailboxController.java:69-70` calls repository-wide `deleteAll()` without a principal; read/count siblings filter by username. The repository has no owner-filtering override and the filter chain requires only authentication. This is a direct cross-user authorization gap, independently of CSRF. |
| Derived progress identity | `container/assignments/LessonTrackerInterceptor.java:56-76` strips `csrf-` before progress lookup/save. `container/users/UserForm.java:18-19` accepts the prefix; `UserValidator.java:27` checks only exact-name duplication; registration accepts the validated account. A registrable `csrf-victim01` can target progress under `victim01`. This concerns progress integrity, not password access or authentication as the victim. |

Spring's [MultipartFile contract](https://docs.spring.io/spring-framework/docs/current/javadoc-api/org/springframework/web/multipart/MultipartFile.html#getOriginalFilename()) also warns that the client filename can contain path information and parent segments. The source review did not cover all remaining platform handlers, challenge chains or lesson packages.

## Proposed implementation sequence

1. **Repair inventory reliability (F1-F3).** Add regression cases to the existing scanner tests, implement the grouping/boundary/omission behavior, and update output consumers and coverage guidance together. Acceptance is observable behavior, not a longer checklist.
2. **Repair eval preparation and grading (F4-F6).** Fix scrub behavior, make residue checks explicit, and version the corrected rubric. Rebuild target copies from pinned revisions. Keep historical results labelled with the scrub/rubric versions they actually used.
3. **Make run provenance mandatory.** Before launching auditors, save target commit, pre/post-scrub tree hashes, scrubber revision, skill revision, rubric revision, full prompt, exact model/settings, tool permissions, delegation policy and budget. Record complete/interrupted status and preserve the full reports and grading evidence.
4. **Trial evidence-backed coverage.** For each reviewed group, require actual handler files and states. For accepted or dismissed candidates, retain attacker, data scope, central controls checked and reason. Reconcile the report with the enumerated surfaces; a checked group name is not proof of review. Evaluate whether grouping duplicate leads by operation/file reduces the cost of the current 982/844-lead inventories without losing useful candidates. These changes are recommendations, not measured gains.
5. **Run a frozen comparison, then repeat it.** Finish or restart both configurations under common conditions, record interruptions, and collect at least three completed pairs to begin characterizing the visible run-to-run spread. Resumed runs need a recorded interruption history and comparable context/budget. Three pairs do not automatically establish statistical significance. Add a held-out multi-file generated-CRUD case with ownership, field allowlists and a safe sibling that has not been used to tune the wording.

Keep detection, calibration and coverage separate. Grade false claims independently and adjudicate valid findings absent from the answer key. Juice Shop G37 combines many XSS sinks into one point while other rows concern a single operation, so a 40-point result is not the fraction of all vulnerabilities found. WebGoat lesson scores remain coverage of a labelled training surface.

### Provenance gap to resolve before rerunning

The current [eval procedures](../README.md) clone default-branch HEAD, while the rubrics name fixed commits. The supplied WebGoat POM says `2026.6-SNAPSHOT`, but its rubric describes `2026.5-SNAPSHOT` at `e7b1313`. With `.git` removed and no retained upstream-revision manifest, this review cannot certify that the supplied copy is the historical pinned tree. The discrepancy does not by itself prove whether the copy or the rubric's version label is wrong.

Fingerprints of the copies used in this review:

| Copy | Enumerated-tree SHA-256 |
| --- | --- |
| Juice Shop | `47771c46bb9649751f9599aa47ac1af80444d460d26c6530f4ff920210173637` |
| WebGoat | `e3bd8fff58dcc591ff9b668173a27f35b12a46ed5e69d705eae8a509bc7f1a6a` |
| `next-store` | `9201e5e001cf9ba7efb2a38e48d93354abae8114d5e4f513fa1f6b1e8dca91d7` |

Fingerprint method: apply `sorted(files)` to the `Path` objects enumerated by the reviewed inventory's `_walk()` on Windows; feed each UTF-8 relative POSIX path, a NUL byte and the binary SHA-256 digest of its contents into an overall SHA-256. Reproduction requires the same path ordering. This includes enumerated oversized/binary files and excludes directories skipped by the walker. It identifies that enumerated tree, not an upstream commit or successful reading of every file by the scanner.
