# Java and Kotlin

Covers Spring Boot/MVC/WebFlux, Spring Security, Ktor, Jakarta EE, Micronaut and Quarkus. Kotlin uses the same libraries as Java; the Kotlin-specific risk is string templates (`"... $id"` or `"${x}"`) doing the same job as concatenation.

## Entry points and enforcement

- **Entry points:** `@RestController`, `@Controller`, `@RequestMapping`/`@GetMapping`/`@PostMapping`, `@RequestParam`, `@PathVariable`, `@RequestBody`, `@ModelAttribute`, `@RequestHeader`, `@CookieValue`, functional `RouterFunction`s, `@MessageMapping` (STOMP/WebSocket), `@KafkaListener`/`@RabbitListener`/`@JmsListener`, `@Scheduled`, `@SchemaMapping`/`@QueryMapping` (Spring for GraphQL), JAX-RS `@Path`, Ktor `routing { get/post(...) }`, `call.receive<T>()`, `call.parameters`.
- **Enforcement:** `SecurityFilterChain` beans and `authorizeHttpRequests` rule order, `permitAll()`, `web.ignoring()`, `@PreAuthorize`/`@PostAuthorize`/`@Secured` (no effect unless `@EnableMethodSecurity` or the older `@EnableGlobalMethodSecurity` is active), custom `HandlerInterceptor`s and filters, Ktor `authenticate("...") { }` blocks (routes outside them are public), JPA/Hibernate filters or repository methods that scope by tenant or owner.
- **Path matching:** confirm security matchers and handler mappings interpret paths identically: trailing slashes, suffixes, encoded segments and `;` matrix parameters. A replaced `StrictHttpFirewall` (for example with `DefaultHttpFirewall`) widens the gap.

## Topic leads

| Topic | Leads | Safe defaults and notes |
| --- | --- | --- |
| SQL injection | `createNativeQuery(` or `createQuery(` with concatenation/templates (HQL/JPQL injection), `JdbcTemplate`/`NamedParameterJdbcTemplate` with built SQL, `Statement.execute*`, MyBatis `${}` (raw substitution), jOOQ plain-SQL `DSL.field(String)`/`DSL.condition(String)`, `JpaSort.unsafe`, `ORDER BY` from input, Exposed `exec("...$x")` | Spring Data derived queries, `@Query` with `:param`/`?1`, MyBatis `#{}`, `PreparedStatement` placeholders and the Exposed DSL bind values |
| Command injection | `Runtime.getRuntime().exec(`, `ProcessBuilder(`, especially with `"sh", "-c"` or `"cmd", "/c"` | `exec(String)` tokenizes on whitespace without a shell, but user-controlled tokens can still inject options |
| XXE | `DocumentBuilderFactory`, `SAXParserFactory`, `XMLInputFactory`, `TransformerFactory`, `SchemaFactory`, `XMLReader`, `SAXBuilder` (JDOM), `SAXReader` (dom4j), `Unmarshaller` from an unhardened source | Fix with `disallow-doctype-decl` or the equivalent feature per factory; see the [OWASP XXE cheat sheet](https://cheatsheetseries.owasp.org/cheatsheets/XML_External_Entity_Prevention_Cheat_Sheet.html) |
| Insecure deserialization | `ObjectInputStream.readObject`, `XMLDecoder`, XStream `fromXML`, Jackson `enableDefaultTyping`/`activateDefaultTyping` with a permissive validator, `@JsonTypeInfo(use = JsonTypeInfo.Id.CLASS)` or `MINIMAL_CLASS` on `Object`/broad base types, SnakeYAML `new Yaml()` before 2.0, Kryo with registration disabled, Hessian, RMI/JMX endpoints | XStream 1.4.18+ uses an allowlist by default; SnakeYAML 2.0 rejects global tags by default; kotlinx.serialization only instantiates registered subclasses. Fix with data-only DTOs or `ObjectInputFilter` |
| SSTI and expression injection | `SpelExpressionParser.parseExpression(` on user input with `StandardEvaluationContext`, Thymeleaf `__${...}__` preprocessing, controllers returning a view name built from input (`return "page/" + lang`), FreeMarker `?new`/`?api`, Velocity/Pebble templates from user strings, OGNL, JEXL, MVEL, `ELProcessor` | Use `SimpleEvaluationContext` for SpEL; FreeMarker `TemplateClassResolver.SAFER_RESOLVER` or stricter |
| Path traversal | `new File(base, input)`, `Paths.get`/`Path.resolve(input)`, `ResourceLoader.getResource(input)` (accepts `file:`/`classpath:` prefixes), `ZipEntry.getName()` during extraction (zip slip), `ResponseEntity` serving a `FileSystemResource` | `Path.normalize()` followed by `Path.startsWith(base)` is component-based and correct; `String.startsWith` is not. Use `toRealPath()` where symlinks matter |
| SSRF | `RestTemplate`, `WebClient`, `java.net.http.HttpClient`, OkHttp, Apache HttpClient, Feign with dynamic URLs, `new URL(input).openStream()`/`openConnection()` | `java.net.URL` also handles `file:` and `jar:` schemes. Check redirect following and resolved-address validation |
| Access control and mass assignment | missing `@PreAuthorize` on service methods, repository `findById(id)` without owner/tenant filter, `@RequestBody`/`@ModelAttribute` bound directly to JPA `@Entity` classes (role, owner, tenant fields writable) | Use request DTOs or `@InitBinder` `setAllowedFields` |
| CSRF | `csrf().disable()` / `csrf { it.disable() }` on cookie-session apps, `ignoringRequestMatchers` | Spring Security enables CSRF by default for servlet apps. Disabling it is fine for stateless bearer-token APIs. `CookieCsrfTokenRepository.withHttpOnlyFalse()` is the normal SPA pattern |
| CORS | `allowedOriginPatterns("*")` or broad patterns with `allowCredentials(true)` (reflects any origin), `@CrossOrigin` without attributes on sensitive endpoints, Ktor `install(CORS) { anyHost() }` with credentials | `allowedOrigins("*")` with credentials is rejected at startup |
| Information disclosure | `management.endpoints.web.exposure.include` containing `*`, `env`, `heapdump`, `threaddump`, `configprops`, `loggers`, `jolokia`, `gateway`; management on the public port; `server.error.include-stacktrace`/`include-message: always`; `spring.h2.console.enabled=true`; Swagger UI with sensitive examples | Only `health` is exposed over HTTP by default ([Spring Boot docs](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html)); a heap dump can contain secrets and sessions |
| Host header and proxies | `server.forward-headers-strategy`, `ForwardedHeaderFilter`, Tomcat `RemoteIpValve` `internalProxies`, Ktor `install(XForwardedHeaders)`, `ServletUriComponentsBuilder.fromCurrentRequest` in reset or invitation links | Forwarded headers must only be trusted from known proxies |
| JWT | jjwt `parse()` before 0.12 (accepts unsigned tokens; use `parseClaimsJws`/`parseSignedClaims`), Auth0 `JWT.decode` used for authorization, custom `JwtDecoder` without validators, `NimbusJwtDecoder` without issuer or audience validation | Spring resource server validates signature and timestamps; issuer and audience need explicit configuration |
| Sessions | `sessionFixation().none()`, long `server.servlet.session.timeout`, `remember-me` with a static key | Spring Security migrates the session on login by default |
| WebSockets | STOMP endpoint `setAllowedOriginPatterns("*")`, missing message-level authorization for `@MessageMapping` and subscription destinations | Check CSRF handling on STOMP `CONNECT` for the Spring Security version in use |
| GraphQL | Spring for GraphQL `@SchemaMapping`/`@BatchMapping` and DGS `@DgsData`/`@DgsDataLoader` on nested fields without the owner check the root `@QueryMapping` has; `@PreAuthorize` on resolvers without `@EnableMethodSecurity`; no `MaxQueryDepthInstrumentation`/`MaxQueryComplexityInstrumentation` bean; custom `DataFetcherExceptionResolver` returning `ex.message`; `spring.graphql.graphiql.enabled: true` in production; rate limiting in a servlet filter that counts HTTP requests rather than operations | Introspection is on by default (`spring.graphql.schema.introspection.enabled`); GraphiQL is off by default. See [graphql.md](../graphql.md) |
| Dependencies | `pom.xml`, `build.gradle(.kts)`, `gradle.lockfile`, version catalogs (`libs.versions.toml`); notable history: `log4j-core` < 2.17.1, Spring Framework data binding (CVE-2022-22965), Spring Cloud Gateway actuator (CVE-2022-22947) | Use the resolved dependency tree (`mvn dependency:tree`, `gradle dependencies`) when available and permitted |
